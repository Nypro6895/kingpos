Layout interaction and keyboard repair - 2026-11-19

Scope
- Fix all24 grouped affected families from the read-only layout audit.
- Ordinary blockers: Settings Change avatar, Add phone actions, Custom service
  on short landscape screens, Forum post-actions containment.
- Keyboard families: Settings/password, Campaign/Admin, POS/Staff/receipt/
  Check Writer/Tax/Service Relay, Gift, quick workspace, social reports,
  My Place, Beauty, Forum dialogs and QuickBooking.

Approach
- components/use-overlay-viewport.ts is opt-in per active affected overlay.
  Ordinary layout is retained when the visual viewport is not reduced; pinch
  zoom and an already-resized layout viewport do not receive another inset.
- Each overlay owns its listeners, coalesced animation frame, styles and cleanup.
  Focus reveal scrolls only modal panels, with explicit nested sticky-edge
  ownership and two bounded measurements when scrolling activates a footer.
- Existing use-dialog-viewport, shared navigation/keyboard tracker, and existing
  account phone/email verification layer are preserved.
- Settings portals escape clipping and preserve nested verification focus,
  busy refusal, parent drafts and navigation/Activity cleanup. Account actions
  become static only inside that dialog context.
- Forum containment is suspended only on the card whose action menu is open.
- Financial handlers, amounts, request identities, permissions, publication,
  booking/payment and provider behavior were not changed by these layout edits.
