# Native advertising transport compatibility — source candidate

Implemented 18 November 2026 (America/Chicago), baseline `a4fe43e2da823586f52b1a5a4f309d0769b3d14d`. No provider, production, Apple, account or native-device requests were made. This is a source patch; the installed app remains unchanged until regenerated bundled assets and a new signed native build are accepted.

The existing native adapter already sent GPS owner selections through `http.shell.campaigns`, a nonretained native read whose arguments travel in an HTTPS POST body. It required GPS, preventing the approved manual/query-only selection. Unmapped `/api/advertising/reports` fell through to ordinary fetch; the bundled custom-scheme resource handler accepts GET files only, so that fallback was not an authorized server transport. Platform admission now carries an encrypted selection proof exceeding the former event limit. Original POST handlers also require `application/json`, which the native event forwarder had not set.

The patch keeps the existing transport and original authoritative handlers:

- Owner `kind: select` accepts paired valid GPS or manual/query inputs, preserves explicit `batch: false` and empty query, adds an allowlisted `selection: '1'` read argument, and reconstructs the exact JSON POST on the server. Location/query remain in the native read body; that resource is not retained. Legacy GET and GPS read shapes remain supported.
- `/api/advertising/reports` maps only to `http.shell.advertising-report`, with one strict `{input}` argument and the exact five-field report DTO. The existing original handler freshly resolves the actor, verifies the encrypted proof against that actor, checks existing immutable receipts, and invokes the original abuse gate before new report admission.
- Only an exact platform `event: view`, `phase: reserve` object with a signed disclosure proof can use the 40,000-byte event allowance. Other event bodies, including confirm/click, retain the 2,048-byte bound. Reports are limited to 40,000 UTF-8 bytes; selections to 2,048. The existing streamed 262,144-byte outer command limit is unchanged. Other commands receive no larger allowance.
- Generated HTTPS requests use the canonical handler path, current request cookie/proxy headers, explicit JSON Content-Type and canonical Origin, with no Referer. Caller headers, URL and identity are not command authority. Original response cookies are applied to the real HTTPS cookie jar and never serialized into the JS DTO. `private, no-store` and `no-referrer` response headers survive the bridge.
- Scope is checked before dispatch after asynchronous body parsing and again before response delivery. An uncertain command is not retried by the adapter. The current native grant, command-scope and original server authorization gates remain in place.

`APP_LOCAL_SHELL_COMMANDS` and the read argument list are the existing generator inputs. `scripts/build-app-local-bundle.mjs` generates signed command metadata from these lists. No Swift or device-permission change was needed: the current Swift transport already supports public grants, body-only campaign reads and bounded generic declared commands. No old generated bundle was manually altered. Native regeneration, signing/archive, upload and physical-device acceptance remain pending under the coordinated release.
