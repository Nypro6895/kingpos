REPRODUCED AND FIXED
1. Shared named-resource loader announced refreshing before consulting its read cache. A fresh seed followed by mount/focus performed zero host reads, yet rendered false -> true -> false. Move the announcement into the cache fetcher so only actual reads announce work. Applies to native/local ReadView consumers, including Bookings, Today, Staff, Market, Settings, and other named views.
2. SelectedBookingDetails treated a successful authorized response with booking:null as still loading. Now it settles with an unavailable message, retry, and Close. A browser regression test failed waiting for the terminal state before the fix and passed afterward.
3. Bookings eligibility timer and focus handler used the manual force-refresh path. Use freshness-aware revalidation on web and local adapters, a shared focus/online/native-foreground scheduler, and a 30-second automatic-attempt gate. Keep manual/mutation refresh forced. Store automatic callbacks in a ref so callback-only rerenders do not restart the eligibility clock.
4. Updating records was a conditional paragraph above the tabs. Place the existing status inside the heading so refresh does not move tabs or the list. Browser geometry is identical during refresh at 320, 390, and 1280px.
