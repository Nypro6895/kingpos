## Report and retry boundary

The server proof is AES-256-GCM with fresh IV and actor/kind authenticated data, using the existing lazy advertising-secret mechanism. It is an opaque POST-body value, never a public URL or log. Strict typed schemas bound targets, public snapshots, redacted summaries, enums, paths, dates and sizes. The report HTTP route enforces same origin, JSON content type and a streamed 40 KB body limit before decoding. Owner selection POST is bounded to 8 KB.

The server derives the signed-in actor or a separate HttpOnly report-actor cookie. Purpose-separated HMAC guest identity is distinct from the advertising visitor/network identifier. The intake RPC independently resolves canonical owner/custom/platform targets and active identity. Reporter-supplied context cannot grant case access or establish an advertising target.

An authenticated exact receipt lookup runs before expiry/new admission/rate checks. An expired authentic proof can acknowledge a completed exact attempt; it cannot create a new report. New reports require a live proof and abuse admission. Logical payload hashing excludes changing ciphertext. Known validation/authorization rejection permits editing; transport/unclassified uncertainty locks reason, details and UUID for an exact retry. Provider/database exception text is never returned or logged by this flow.

Only dispatched uncertain attempts are stored in session storage: actor scope, creation time and the exact UUID/kind/encrypted proof/reason/details. There is one unresolved attempt per actor scope (authenticated identity is shared across both ad kinds; anonymous report cookies are separately scoped by ad kind), at most three actor scopes, 40 KB per entry / 120 KB total, and a 30-minute validity limit. The code refuses a fourth rather than evict another actor’s unresolved attempt. Expired entries are rejected/pruned on access; browser shutdown/crash is not a physical deletion deadline. Unsent drafts and the plaintext Why DTO/GPS/query/visitor hash are not stored. User-entered report details can themselves contain sensitive text; the UI asks users to avoid it.

Actor changes hide forms/Why data and synchronously fence responses, while retaining another actor’s opaque uncertain receipt for that actor’s own return. No automatic resend occurs. A→B→A recovery uses the original payload/UUID; B cannot display/replay A’s form. Async success/rejection compares both scope and request UUID before clearing. Storage failure blocks sending. Confirmed attempts are cleared; unsent cancel keeps only the in-memory draft. Recovery is bounded to the TTL/tab session, not a promise of permanent recovery after storage loss.
