Behavior
- An explicit manual/typed area wins GPS. Canonical valid salon coordinates
  establish geographic eligibility; missing/stale pins never invent distances.
  Existing bounded Census/owner geocoding and coordinate authority are retained.
  Recognized US services work before or after a verified area (dip powder
  Chicago / Chicago dip powder), using the same single bounded entity lookup.
- Relevance: local area, then evidence appropriate to name/service/style intent,
  then profile completeness plus a capped actual-public-post boost and newest
  post tie-break. The initial activity cap is five posts, up to ten extra points.
  Imported reference introductions do not count as salon activity.
- Whole-word service evidence prevents gel matching inside Angel/Gelato. English service
  stems handle singular/plural; specific US services retain required keywords.
  Exact/quoted public brands still override tentative service/place parsing.
- No-hit checks use indexed producers rather than repeated whole-table probes.
  Typo-name probes use conservative edit signatures and compact-name prefixes,
  followed by the unchanged trigram/score proof. Unsupported probes retain the
  original visible index predicate. Generic typos can still inspect a regional
  cohort; the candidate/page limit is not a universal bound on index work.
- Style/post matches require evidence from one current public post, with
  moderation/block/owner/source proof. One salon per result. Outside-area actual matches remain labelled
  Suggestions; generic category-only filler does not become a keyword match.
  Current-post proof uses the unique content-key lookup before the remaining
  checks. This prevents a historical/current self-join from rescanning all of a
  salon's posts for every historical row when statistics are stale.
- Service keywords use the whole active salon catalogue, including descriptions.
  Several catalogue items can jointly satisfy the words: Gel pedicure plus
  Regular manicure can match gel manicure. This is keyword discovery, not proof
  of one exact bookable menu item. The first eight displayed service names are
  not used as a filter, because doing so would lose valid later services.
- New relevance sessions use indexed evidence lanes ordered before LIMIT;
  merge/queue64, normal search page12, API maximum20 and stable viewer-bound
  keyset cursors. Full local batches avoid unnecessary broader-area probes.
  Old v3 sessions retain their shipped continuation path.
  New Closest/newest sessions use the indexed lanes; ready canonical Trust/Bookable
  retains its existing scorer/order. Geographic quality probes use cells and
  exact distance before each bounded merge, rather than sorting every point.
- Each live-metadata request uses a visible window of at most36 salons; initial
  and continuation sections keep separate bounded observers. IntersectionObserver
  avoids measuring every card on scroll. Updates/withdrawal tombstones survive
  same-session page append; identity reset clears and suspends the old session.
  Offscreen card rendering can be skipped by browsers supporting content-visibility.
- One database-timeout retry remains capped and now has cancellable350ms
  backoff. New cancelled requests cannot start subsequent enrichment RPCs.
- Operational metrics distinguish first page, continuation and bounded refresh,
  along with the actual ranking/sort path, without logging search text or GPS.
