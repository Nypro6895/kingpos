# iOS role-aware read preparation

Implementation for the approved Owner, Staff and Personal loading plan. Baseline is the clean combined web source `699101149dbf5614ae17ab601b5e306ed311664c`, whose installed client bundle matches uploaded iOS 1.0.0 (53). This change is implementation work; it does not authorize a separate production release or TestFlight upload.

The installed app prepares ordinary read DTOs without mounting hidden page trees. The active page's first data comes before metadata and speculative work. A shared queue runs at most two reads, including at most one speculative read; selecting a page promotes its existing read and lower-priority work resumes later. Request identities, cancellation and scope resets prevent an old account or page response from replacing current data.

Owner prepares Today, its server-dated permitted sections, Book/Profile/Notifications, POS/Tickets/Reports, Customers/Staff/Services/Payroll and ordinary More/My Place data. Staff prepares My Work, Appointments, Post, Workday and personal payroll/analysis using the trusted staff binding. Personal prepares Explore, Bookings/Beauty/Activity, My Place and saved/following/favorites. Existing server authorization remains authoritative for every read. Forms, payment/control endpoints and commands are excluded. An online-only Staff proof is not background-read authority. Shared Staff reads may remain RAM-only under the existing native lease policy.

Explore prepares upcoming content within roughly 2.5 viewport heights, at most three continuation pages per advance. Its budget is shared across recommendation stages. Background work yields when hidden/offline, on Save Data or 2G, and after scope/query/area changes. Finite snapshots cover current filters and periods; this is not a complete historical database replica.

Native disk restoration gets a 60ms head start before an online read can proceed. Disk snapshots with a skewed timestamp cannot replace fresh network data. Empty Set-Cookie responses avoid one redundant WebKit cookie snapshot while retaining authority comparisons. Correlated native diagnostics now measure cookie capture, reconciliation and awaited persistence separately from HTTP; none of these measurements alone proves a usable rendered frame or durable save.

Validation evidence is recorded under `artifacts/ios-priority-prefetch-20261027/`. Browser integration exercises real React/resource/queue code with controlled native transport and disk boundaries; it is not a physical iPhone latency benchmark. Native XCTest and an unsigned archive must be validated before the change is ready for integration. A new native build is required because both bundled JavaScript and Swift changed. Integrate with the current web/native baselines under the release policy; do not independently publish this checkout.
