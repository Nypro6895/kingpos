Request: fix staff posting error and queue with the next combined deployment.
Change ID: staff-post-safari-webp-fallback
Status: locally tested; needs integration with exact production baseline; NOT deployed.

Cause:
The screenshot message comes from compressImageCanvas in lib/image-upload-client.ts.
It rejects canvas output unless its MIME type is image/webp. A browser may decode
WebP but lack canvas WebP encoding, returning PNG instead. This fails before the
post is submitted; changing staff authorization would not fix this error.
The affected physical iPhone has not been tested in this task.

Fix:
- Keep native WebP encoding on browsers that support it.
- Send fallback cropped PNG/JPEG pixels to authenticated POST /api/images/normalize.
- Reuse normalizeImage for genuine WebP, metadata stripping, pixel and byte limits.
- Check response MIME, size and dimensions before uploading. Do not relabel PNG as WebP.
- Stream-limit server input to 10 MB, reject cross-site requests, disable response caching.
- If fallback PNG exceeds 10 MB, shrink the canvas and retry before conversion.
- Existing post/storage authorization is unchanged. No migration or native bridge change.
