INTENT, CHANGE AND IMPACT

1. My Place
Original account context already provides admitted user/workspace/salon rows. The route nevertheless awaited requests, phone inspection and owner invitations together before returning any page content. Those reads have real purposes: requests/invites control their actions; phone inspection supplies profile verification and precedes profile-dependent controls. They are not unnecessary data.

Hosted route now returns the actual shared view from admitted context and streams those three optional results into small independent Suspense fragments. Real workspace search, known owner/staff rows, Details and original document workspace switching no longer wait for optional requests/invites/phone. Counts and request/invite rows wait for their real result; pending is not a settled empty list.

Unknown phone inspection, including non-ok inspection results and thrown reads, is distinct from false verification. Profile-dependent controls stay withdrawn until inspection is known. An already mounted personal-profile editor is hidden and inert while verification is unknown, preserving its unsent draft for a successful retry. Initial unknown does not mount an editor. Request/invite failures show local retry and do not discard known workspace rows. Existing create/salon/activity/apply panels, request operations, locks, Save/Cancel and navigateToWorkspace remain.

Native retains its original settled page.my-place reader and DTO, using a neutral bundled MyPlaceLoading frame until acceptance. This wave does not split native context/phone/request transport or claim the native workspace list appears before that composite read.

2. Services
The full workspace DTO intentionally includes view/manage authority, staff/add-on/booking readiness and the editor's source values. It remains necessary. The existing private catalog pilot and its disabled/default flags remain unchanged.

ServicesManager now has an explicit unresolved state. Its real toolbar can render without an invented accepted DTO: pending disables form controls and hides catalog counts, empty-catalog/read-only claims, editor/drawers and save bar. Native keeps that manager mounted while the existing scoped page.services reader resolves; accepting a DTO enables the original view without replacing toolbar/query state. Background reads keep accepted data and existing drafts. Authoritative DTO data remains NonNullable; presentation null does not widen transport acceptance.

Hosted leaf/loading/auth fallbacks use the same public-only pending manager before original admission/view permission/workspace reads complete. Cold hosted Suspense replaces its fallback with the loaded client; this is visual continuity, not permanent toolbar DOM identity across that replacement. Original context/view/manage gates still precede protected content/actions. Original editing, beforeunload/document-link discard confirmation, same-scope refresh, Save/Cancel, expected salon and scoped catalog invalidation remain. Saving is explicitly rejected while unresolved/no-manage, and Save all is disabled after manage permission loss.

3. Notifications
Original route awaited both the first feed page and pending action summary. Existing authorized client GET, scoped 15-second cache, pagination/window reconciliation, viewed events, focus/poll and retained Activity already own subsequent reads.

Hosted now mounts the actual authenticated client in explicit pending mode and delegates the first feed to that existing GET/cache reader. The original pending summary streams independently into a bound action slot. Header/All/Unread remain available while the feed waits. No empty pending seed becomes current. Warm cache can satisfy an ordinary return without a duplicate first feed read. Summary internals still perform their original count/notification reads; this is not zero server notification reads.

Tradeoff: cold feed starts after client hydration instead of its old SSR feed-list read. The change removes the full-page feed gate and supports existing warm-cache reuse; it does not establish lower total cold-feed latency. No total-latency percentage is claimed.

Viewed metadata can patch/cache only an accepted current feed, preventing an external shell-viewed event from creating a fresh empty cache during a cold pending read. Request generations and scope/reset withdrawal reject late rows and old private action slots. No authenticated scope means no private seed, first GET or write. Authoritative denial still revokes the shared cache and invokes existing reauthorization/reload behavior; Retry cannot reopen a revoked scope. A new admitted source can recover separately. Mark all viewed keeps one POST and the existing refresh listener owns one subsequent GET.

Native keeps the original composite page.notifications reader, showing a neutral frame while it waits. It does not mount a competing client GET. Accepted client is keyed by admitted scope. Native JSON metadata retains required settled feed/cursor/action fields and excludes deferred web-only presentation props.
