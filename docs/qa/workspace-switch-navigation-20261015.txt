Problem and fix
Earlier real-auth salon QA observed switching from /salon-profile to personal
unexpectedly returning to My Place with a workspace error. The previous Server
Action changed workspace cookies while the old salon page remained mounted.
Its mutation notification could refresh experience scope before the client
router reached the destination, exposing the old route to the new context.

Desktop/mobile account menus, My Place, QuickWorkspacePanel and legacy workspace
forms now open the existing /workspace/open handoff as a document navigation.
The server route checks current membership and the allowed destination, writes
context, then redirects. Account rows use each workspace's canonical home;
shortcuts retain their explicit destination. Same-workspace navigation remains.
No auth, membership, cache-isolation, database or native bridge rules changed.
