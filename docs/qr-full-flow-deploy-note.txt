Fixes established by this follow-up
- Personal check-in now issues the canonical Check-in Receipt number from the
  salon's daily counter. Previously it fell back to the relay's global identity
  and did not create the daily receipt row. Customer QR, Staff and POS now agree.
- One private receipt issuance core supports both the existing paired display
  and authenticated Personal check-in. Reusing an account-owned visit created
  earlier at the front desk preserves that visit's original metadata. Anonymous
  display callers retain their origin/pairing checks; the helper is not callable
  through client RPC roles. Existing counters/receipts are reused, not reset.
- Ready is consumed when a visit leaves Waiting. Cancelling an empty Holding
  cannot revive the old Ready banner. Retrying the old request remains harmless;
  an intentional new Ready request after cancellation can notify the customer.
- Personal service selection now reflects the existing check-in maximum of
  eight services. UI blocks excess choices and the RPC returns a specific error.
  Staff service/amount lines keep their existing separate limits.
