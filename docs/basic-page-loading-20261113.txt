IMPLEMENTED ORDINARY GROUPS

1. Staff Scan /staff/scan
The leaf previously awaited Staff identity and the entire Scan workspace before returning its title/button. It now streams the existing neutral Scan frame through a leaf Suspense and route-specific loading fallback. The identical neutral frame may appear during the existing retained-page auth gate. It contains no identity, customer, code, camera or action capability. Original getStaffPortalIdentity and scoped loadStaffScan remain before the protected client.

The successful authorized server seed receives an initialReadAt completion timestamp. Exactly the first activation can reuse it when its known age is 0–<15 seconds; missing/failed/old/future-clock seeds take the original refresh path. Same-scope draft reconciliation still runs. This is not a new authorization lease or a durable cache. Realtime/reconnect/poll and Activity reveal continue to read current work. An epoch-owned in-flight guard fixes a reproduced case where a hidden pending read prevented a fresh reveal read and its old finally could interfere with a new request.

The existing client now owns ordinary reveal reconciliation without a duplicate full RSC refresh; generic 30-second auth validation is retained. The original online HTTPS exception, Staff binding, plugin availability, camera/decoder, connect/save/cancel, ticket revision, POS Submit and draft authority remain. This does not turn Scan into a newly bundled native route or promise zero document navigation in the installed app.

2. Personal QR /qr
A public-only frame with My QR / Personal ID / disabled Scan salon QR appears while the original user and workspace/catalog readers wait. Route-specific loading and the existing Activity reset/auth gate use the same safe frame; native named-read cold loading also shows it instead of generic Opening. No code or camera is shown before fresh accepted data. Existing query handoff, viewer+entry+visit+scan keys, unknown/secret reset policy, code expiry, idempotent check-in and all actions remain.

This preserves a necessary fresh-capability load while avoiding a blank generic page. A cold Suspense fallback is replaced by the real client when ready: this is visual continuity, not a claim of permanent header DOM identity or faster RPCs.

3. Membership /membership
The exact public reading route has an explicit browse policy. Its existing public frame streams before mutable published plans/copy; no prices are hardcoded. Monthly/Annual state is retained on ordinary return. Original public RPCs and admin preview/default framed presentation remain. Secret/hash/action/unknown-child rules stay conservative. Authenticated shell validation still applies where required.

4. Rewards /rewards
The exact ordinary wallet route has an authenticated memory browsing policy. Its existing scoped named wallet hook already owns refresh/reconnect, epoch rejection, transient-error retention and reset; ordinary return does not also refresh the entire RSC tree. Server authorization and fresh balances/actions remain unchanged. Gift Cards is a mixed bearer/transfer/payment surface and was not switched to a blanket browsing policy.

5. Installed More /more
The actual menu can render from already admitted explicit workspace access flags while page.more checks the optional Campaign entitlement. Campaign remains absent until the resource accepts installed:true. Same read identity, command guards and original menu links remain. Missing/ambiguous access, unavailable scope, error or denial do not expose this early menu. Reset/new-account scope rejects a late previous result.

6. Hosted Customers /customers
The original actor, customers.view, management controls and timezone admission precede the actual toolbar. Only metrics/list/duplicates/pagination wait under a keyed Suspense. The search input and toolbar stay mounted while rows complete. Existing query/page arguments, merge forms and permissions remain; no dummy customer or total is shown. This is post-admission row streaming, not a claim that private initial admission is bypassed or that an installed cold DTO was split.

7–8. Hosted Saved posts and Following
/more/saved-post (including saved-designs alias) and /more/following render their original filter/search controls after user admission, with rows/pagination in keyed Suspense. Search text typed while rows wait survives their completion. Removal actions, source identifiers, pagination and legacy favorite-shop/favorite-customer redirects are preserved. Other More sections are not claimed optimized by this particular streaming change.

DESIGN BOUNDARIES

- pendingFallback is opt-in and public chrome only. The shared ExperiencePageBoundary still hides private children during reset/auth checks and waits for the original revision/grant outcomes. No global unknown policy is relaxed.
- Resource, account, salon, period and permission identities are retained. No global cache rewrite, new SQL, financial formula, mutation retry or capability grant is introduced.
- Existing POS/Portable lock/cart/outbox, Check Writer, Tax no-store and Payroll edit/navigation guards are outside this patch.
- Published reference content can change; it is reconciled through its original readers. Operational/private values are not bundled as static data.

LIMITS / NEXT ACCEPTANCE
